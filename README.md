# Validate Doctoc TOCs in CI

GitHub Action to validate that the table of contents generated by
[doctoc](https://github.com/thlorenz/doctoc) is up to date with your markdown
files. It fails the build if any TOC needs to be regenerated, so you can
enforce up-to-date TOCs in CI.

## Usage

```yaml
- uses: kotanys/doctoc-validate-action@v1
  with:
    # Colon-separated list of shell patterns to check.
    # See "Glob patterns" below.
    files: 'README.md:docs/**/*.md'

    # Doctoc version to install (passed to npm).
    version: '2.5.0'

    # CLI args to pass to doctoc, e.g. '--github'.
    args: ''

    # Print a diff of the stale files if validation fails.
    # Default: false
    print-diff: false
```

## Glob patterns

Each pattern from the `files` input is expanded by bash, so the usual shell
globbing applies. Among others, the following shell options are set:

- `globstar` is **enabled** — `**` matches any number of directories, so
  `docs/**` matches everything under `docs` recursively. This includes
  directories themselves (e.g. `docs/`), but those are skipped with
  a note in the output.
- `nullglob` is **enabled** — a pattern that matches no files expands to
  *nothing* instead of staying literal. As a consequence, a pattern that
  matches no files is silently skipped and **nothing is validated**.

> [!WARNING]
> Patterns cannot contain `:`, spaces, tabs, and newlines.
> This limitation may be lifted later if it becomes a problem.

## Scenarios

### Validate a single file

```yaml
- uses: kotanys/doctoc-validate-action@v1
  with:
    version: '2.5.0'
    files: 'README.md'
```

### Validate all markdown files recursively

```yaml
- uses: kotanys/doctoc-validate-action@v1
  with:
    version: '2.5.0'
    files: '**/*.md'
```

### Validate several subtrees and print the diff on failure

```yaml
- uses: kotanys/doctoc-validate-action@v1
  with:
    version: '2.5.0'
    args: '--github'
    files: 'README.md:docs/**'
    print-diff: true
```
